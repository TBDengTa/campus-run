# 考勤录入水印相机方案（检查留证照片 · 时间 / 对象 / 检查人烙进图片）

> **状态：已实施（2026-11-13）。** 口径定稿 + 代码落地均完成；真机验收（iOS + Android，见 §8）与
> 发布前隐私协议勾选「摄像头」为人工事项。本文件是水印相机链路的**口径与边界唯一说明**；
> 与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准。
> 开工前必读：`AGENTS.md`（上传限制解除条款 / UI 令牌 / 编码红线 / `tools/` 约定）、`docs/ui-design.md`。

## 0. 一句话目标

检查录入的留证照片从「系统相机拍什么是什么」升级为**水印相机**：
拍下的瞬间把「检查模块 · 受检对象 + 拍摄时刻 + 检查人」**烙进照片文件本身**，
上传、复审台、管理端看到的天然就是带水印的照片，下游链路零改动。

## 1. 现状盘点（改造前的事实，别凭印象）

| 位置 | 现状 |
|---|---|
| `packageUnion/entry/entry.js::onChoosePhoto` | `wx.chooseMedia({ sourceType: ['album','camera'], sizeType: ['original'] })`，单次 9 张、张数不限 |
| 上传 | `utils/request.js::uploadCheckPhoto` **逐张**上传 `/api/upload/check-photo`，单张失败标记不丢整组，失败先原图、兜底压缩重试一次（用户 2026-11-12「解除所有上传照片的限制」） |
| 服务端 | 不限体积 / 张数 / 画质；文件按内容 SHA 命名存 `/uploads`（`immutable` 缓存）；**本次零改动** |
| 入口 UI | 抽屉照片区一个「拍照 / 相册」按钮（`entry.wxml:459`），`type='photo'` 字段共用 |
| 表单防护 | `entry.js::onShow` 里 `if (this.data.showForm) return;` —— 抽屉开着不重载（2026-10-24「传完自动关闭」事故的修复），**跳相机页往返正好被这条保护** |
| 水印 | 全仓库无任何水印实现；`wx.chooseMedia` 的系统相机**无法叠加任何 UI**，这是必须自建 camera 页的根因 |
| canvas 先例 | `packageAdmin/class-status` 已用 canvas 2d 生成图片（`createSelectorQuery → canvas 节点 → canvasToTempFilePath`；画布「移出屏幕」而非 `display:none`；字符预算折行）—— 合成管线全部沿用这套经验 |
| 位置权限 | `app.json` 已声明 `scope.userLocation` + `requiredPrivateInfos`（GPS 实跑在用）；摄像头权限（`scope.camera`）由 camera 组件首用弹窗，**但小程序后台「用户隐私保护指引」需勾选摄像头**（见 §5.4） |
| 时间工具 | `utils/format.js::formatDateTime` 是 `YYYY-MM-DD HH:mm`（北京时区）——**没有秒**，水印需要秒，要加一个单点函数而不是切片 |

## 2. 目标链路

```
改造前：
  「拍照 / 相册」→ wx.chooseMedia(系统相机, 无水印) → photos[] → 逐张上传 → URL 进表单

改造后：
  「水印拍照」→ packageUnion/wcamera（camera 组件，实时预览叠水印浮层）
       │  按快门 takePhoto(quality:'high')
       │  → canvas 2d 合成：drawImage 原图 + 底部水印条（模块·对象 / 日期 周X 时:分:秒 / 部门·检查人）
       │  → canvasToTempFilePath(jpg, quality:1)   ← 水印已烙进文件
       │  → 预览「用照片 / 重拍」，确认进本会话托盘，可连拍
       │  「完成」→ EventChannel 带回全部照片
       ▼
  entry.onWatermarkPhotos(files) → 走现有 photos[] 管线（逐张上传/进度/失败重试/删除）—— 这一段一行不改
  「相册（无水印）」→ wx.chooseMedia(album only)，按钮文案显式标注（D1 已定稿）
```

## 3. 推荐口径（D1~D10）

| # | 议题 | 推荐口径 | 理由 |
|---|---|---|---|
| D1 | 入口拆分 | 照片区拆两个按钮：**「水印拍照」**（新页）+ **「相册（无水印）」**（`chooseMedia` album-only，不打水印；按钮文案显式标注） | **用户 2026-11-13 定稿：保留相册**（补录说明图等场景仍需），靠文案标注让检查人与复核员知情「这张没走水印相机」。日后要收紧为一行显隐，不再立项 |
| D2 | 水印形式 | **烙进照片文件**（canvas 合成后再上传），不是预览浮层 | 复审台 / 管理端 / 转发出去的图片天然带水印，下游零改动；浮层水印上传后就消失，没有证据价值 |
| D3 | 水印内容 | 三行：`模块名 · 受检对象` / `YYYY-MM-DD 周X HH:mm:ss`（大字）/ `部门 · 检查人姓名`（如 `生活部 · 张三`） | 第一行与抽屉标题同源（`module.name + current.targetName`），保证「记录标题」与「照片水印」一致；第三行部门**用户 2026-11-13 定稿**：取 `/api/union/mine` 下发的 `roles[].deptName`（**服务端单点**，前端不自算；主席团恒为「主席团」，多条记录取第一条非空 deptName，缺失时只写姓名）。连拍每张用**各自快门时刻** |
| D4 | 时间来源 | 按快门瞬间的**本地时钟**（`takePhoto` 回调里取） | 弱网/离线可拍（D9）；本地时间可被修改——水印定位是**留痕与复核辅助，不是防伪凭证**，真锚点是服务端接收时间（§7） |
| D5 | 定位 | **v1 不做**（不调 `getLocation`，不引逆地理） | **用户 2026-11-13 定稿**。受检对象文本已含楼栋/教室（「1号楼302」「1号教学楼201」），位置语义已承载；逆地理要腾讯位置 key（费钱、key 必须放服务端） |
| D6 | 摄像头 | **固定后置**，不做前后切换、闪光灯 UI（`flash="auto"`） | 考勤留证拍的是环境；前置镜像 + EXIF 姿态是两个大坑，v1 直接绕开 |
| D7 | 连拍 | 相机页支持**连续拍摄**：拍一张确认一张，底部缩略图托盘，「完成」一次带回全部 | 检查场景常拍 2~4 张（全景 + 细节）；逐张退出重进太磨人 |
| D8 | 环境回退 | camera 组件不可用 / 初始化失败（PC 端、极旧基础库）→ 提示后回退 `chooseMedia` 系统相机（无水印），**不阻塞检查** | 录入不能因为炫技功能停摆；回退时照片照常入库，只是没水印 |
| D9 | 离线可用 | 相机页**零网络请求**：水印文案全部由 entry 通过 EventChannel 传入（模块名/对象名），检查人姓名读本地登录态缓存 | 检查现场网络差是常态；离线拍完回 entry，照旧走逐张上传（本来就有失败重试） |
| D10 | 服务端 | **零改动**。上传接口、存储、复审台 `cropPhotos`、管理端看图全部不动 | 水印在成像端烙死，服务端看到的就是普通 jpg |

## 4. 水印版式

```
┌──────────────────────────────┐
│                              │
│          照片画面              │
│      （完整原尺寸保留）         │
│                              │
│▓▓▓▓▓▓▓ 渐变黑 55% ▓▓▓▓▓▓▓▓▓│
│ 晚自习检查 · 1号教学楼201      │  ← 行1 模块·对象
│ 2026-11-13 周五 21:04:36     │  ← 行2 大字（视觉重心）
│ 生活部 · 张三                 │  ← 行3 部门·检查人（deptName 缺失时只写姓名）
└──────────────────────────────┘
```

规格（全部**按图片宽度等比**计算，小图不大字、大图不小字；
**横屏照片例外 —— 基准换成图高**，见下与 round2 文档 B6）：

| 元素 | 规格 |
|---|---|
| 底条 | 底部全宽，高 ≈ 三行文字 + 上下 padding；背景 `linear-gradient(transparent → rgba(0,0,0,0.55))`，只压底部不遮画面主体 |
| 行1 模块·对象 | 字号 ≈ W/24 白字，超宽**字符预算折行**（canvas 2d 无自动换行，沿用 class-status 的折行做法），最多 2 行超出省略号 |
| 行2 日期时间 | 字号 ≈ W/15 加粗白字（水印相机的视觉锚点，主流水印相机同款层级） |
| 行3 部门·检查人 | 字号 ≈ W/28 白字 85% 透明度；部门名取 `mine.roles[].deptName` 服务端单点下发 |
| 输出 | `canvasToTempFilePath({ fileType:'jpg', quality:1 })`，**原尺寸合成**；仅当长边 > 4096px 才等比降采样（takePhoto 'high' 极少触发，防低端机位图爆内存） |

⚠️ 上表的「按 W 等比」只适用于**竖屏**（第一轮已验收）。横屏照片 W≈1.33×H，
按 W 定字号会把底条撑到占画面 **42~46%**（4032×3024 → 时间大字 269px、底条 1258px），
复审台看到的照片一半是黑条 —— 这就是用户 2026-11-13「横屏占比太大、还挡画面」在**成片**上的那一半。
现行口径（`utils/watermark.js::computeLayout(outW, outH)` 单点，`LAYOUT_LAND`）：
横屏（W>H）基准取 **H** 并整体收紧一档（f2 = H/24）、行1 折行宽度限到 62% 画面宽，
底条稳定 ≈ **25% 画面高**；竖屏逐字不变（检查器有「竖屏规格零变化」回归护栏）。

时间字符串走 `utils/format.js` 新增的**单点函数**（北京时区、含秒、含周X，复用 `partsInTz` / `parseDateKey` 的既有口径）——禁止任何页面从 ISO 串切片（AGENTS.md 既有红线）。

## 5. 实现设计

### 5.1 新页面 `packageUnion/wcamera`（分包，不进主包）

- 主包已超 2MB（音效条目的教训），新页放 `packageUnion`，`app.json` 分包 pages 补一行。
- 生命周期：`onShow` 首行登录闸门 `if (!getApp().requireLogin()) return;`（AGENTS.md 通用约定）；
  `onLoad` 里通过 `getOpenerEventChannel().on('init')` 收水印文案（模块名 / 对象名 / 部门名），**不发任何网络请求**。
  部门名在 `entry.js::load()` 取 `/api/union/mine` 时顺手存进 data（`roles` 里第一条非空 `deptName`），
  不在相机页重新拉 —— 相机页对部门名只读不算。
- 结构：全屏 `<camera device-position="back" flash="auto">` + 实时**预览浮层**（纯 WXML 定位在底部，
  让用户取景时就看到水印会长什么样——浮层只是预告，真正的水印在合成文件里）+ 快门钮（`.tt-*` 白橙风格）
  + 会话托盘（本会话已确认的缩略图横条 + 计数）+ 「完成」按钮。
- 授权失败（`scope.camera` 拒绝 / 组件 error）：出引导面板「去设置开摄像头」+ 「用系统相机（无水印）」回退（D8）。

### 5.2 合成管线（canvas 2d，唯一实现）

```
takePhoto(quality:'high')
  → wx.getImageInfo(path)          // 拿 width/height/orientation
  → 隐蔽 canvas 节点（「移出屏幕」，不 display:none —— class-status 踩过）
  → canvas.createImage() 载入原图
  → 按 orientation 校正方向绘制（仅 'up' 之外的值需要，预期极少命中；真机验收重点）
  → drawImage 原尺寸 → 画底部渐变 → 逐行 fillText（折行走字符预算）
  → canvasToTempFilePath({ fileType:'jpg', quality:1 })
  → 预览态展示合成结果，「用照片」进托盘 / 「重拍」丢弃
```

- **合成参数与折行规则只写一份**（本页一个纯函数模块），预览浮层的文案拼装与烙图共用同一来源 —— 两处各拼一份必然「预览写着 A、照片烙着 B」。
- `canvasToTempFilePath` 产物**无 EXIF**（方向已烙进像素）：拍摄参数丢失对考勤无碍，反而消除了下游 EXIF 姿态歧义；副作用见 §7。

### 5.3 entry 入口改造（改动最小化）

- `onChoosePhoto` 拆为 `onWatermarkCamera`（`navigateTo` wcamera，`events` 里收 `shot` 回传数组）与 `onAlbumPick`（`chooseMedia` album-only，原逻辑原样）。
- 回传照片并入 `this.data.photos`（`status:'pending'`）后调 `uploadPending(field)` —— **上传/进度/失败重试/删除/表单同步一行不改**。
- ⚠️ 合成文件没有 `size` 字段（`canvasToTempFilePath` 只回路径）：入列前用 `wx.getFileSystemManager().getFileInfo` 补 size，否则失败兜底里 `size < 2MB 跳过压缩` 的判断会把 size=0 的小图也跳过，压缩重试通道静默失效。
- 与 `onShow` 表单防护的关系：相机页是**页面内导航**（不触发小程序 onHide/onShow 重载），返回后 `showForm` 仍在 → 现有防护天然兼容，不另起炉灶。
- 批量录入「无缺勤」不带照片、修改记录复用同一抽屉 —— 均自动获得水印入口，无需单独处理。

### 5.4 权限与隐私

| 项 | 动作 |
|---|---|
| `scope.camera` | camera 组件首用弹窗；拒绝走 §5.1 引导面板 |
| 隐私协议 | 小程序后台「用户隐私保护指引」需勾选**摄像头**（一次配置，发布前确认，代码无关） |
| 位置 | v1 不用（D5），不新增任何位置声明 |

### 5.5 服务端

零改动（D10）。不做「服务端校验水印存在」之类的钩子：客户端合成对服务端不可校验（见 §7 诚实清单），做了就是假护栏。

## 7. 风险与已知边界（诚实清单）

1. **客户端水印不是防伪**：改系统时间、截图重拍、PS 都能绕过。它的真实价值是①复核效率（复审台一眼看到时间/对象/人）②心理威慑③对照锚点——水印时刻与记录所选**时段**（period）不符时，复核员一眼能看出「录的是 21:00 场、拍的是 22:37」。**真正的可信锚点**是服务端接收时间（`FileObject.createdAt`）+ 内容 SHA 文件名，这些已在现网。
2. **EXIF 姿态**：少数安卓机 `takePhoto` 产物带旋转标记，`createImage` 解码不自动应用 → 水印方向错。§5.2 已按 `getImageInfo().orientation` 校正；真机验收必测项。
3. **低端机内存**：4032×3024 位图 ≈ 47MB，>4096px 降采样护栏已设；正常 takePhoto 'high' 几乎不触发。
4. **产物无 EXIF**：拍摄参数（机型/GPS tag）不保留——考勤场景可接受，文档里明说，避免日后有人去找。
5. **PC / 极旧基础库**：camera 组件不可用 → D8 回退系统相机（无水印），录入不停摆。
6. **JPEG 重编码一次**：合成必然重编码（quality 1 视觉无损、体积可能略增）。这是「水印烙进文件」的固有代价，与「解除上传限制」不冲突——限制条款针对的是**不许挡用户的大图**，不是「任何重编码都禁」。

## 10. v1 明确不做

- 前后摄像头切换、手电筒/闪光灯手动开关（`flash="auto"` 兜底）
- GPS 定位 / 逆地理地址（用户 2026-11-13 裁决不做；日后要真实地址另行立项，key 走 `server/.env` 服务端代理）
- 水印模板多套切换 / 水印位置自定义 / 拍照前自定义备注输入
- 视频留证、连拍自动成组
- 服务端任何「水印校验」逻辑（§7.1：假护栏比没有护栏更糟）

## 11. 实施修订（2026-11-13 真机反馈，已落地）

首轮真机测出两个问题，修订如下（口径以本节为准，覆盖 §5.1/§5.2 的旧描述）：

| # | 反馈 | 根因 | 修订 |
|---|---|---|---|
| R1 | 「拍完照片后没有返回，也就是没有确认」 | 旧流程**等 canvas 合成完才出预览**：真机大图解码 / 大画布输出慢甚至**挂死**（既不 success 也不 fail），showLoading 整屏遮罩一挂就是「拍完卡死」 | **乐观预览**：快门成功原图**立即**进确认界面（重拍/用照片马上可见），水印后台合成，完成换带水印图；读图/解码/输出每步 `withTimeout` 6s；画布失败自动降 2048 档重试一次；两档全失败 → 保留原图 + toast「已保留原图」，确认流程照常可用。**不再用整屏遮罩**；合成中「用照片」暂不生效（防把无水印图当成功交上去），重拍随时可用（seq 作废在途合成） |
| R2 | 「没法自动转成横屏」 | 页面没开旋转；且 **iOS 的 `pageOrientation:"auto"` 只在 `navigationStyle:"custom"` 下生效** | `wcamera.json` 配 `pageOrientation:"auto"` + `navigationStyle:"custom"` + `disableScroll`；自定义导航栏（返回钮在托盘有照片时等同「完成」带照片回录入台）。**使用前提：手机系统「竖屏锁定」需关闭**（系统行为，代码只提供旋转能力） |

横拍与 EXIF 的关系：横屏页面下 takePhoto 产物方向随设备/机型而异（`up`/`right` 都可能出现），
`drawNormalized` 按 `getImageInfo().orientation` 校正后画水印，四种旋转全兜住——这一条是 R2 能安全
落地的前提，真机验收必测横拍水印方向。

## 12. 第二轮修订（2026-11-13 真机反馈「拍照后上传失败 / 横屏 UI」，已落地）

口径唯一说明在 **`docs/watermark-camera-round2-plan.md`**，本节只留索引：

| # | 反馈 | 修订落点 |
|---|---|---|
| R3 | 「拍照后上传显示失败，是不是太大了」 | 根因 = canvas q1.0 满分辨率重编码把成片放大到 10~20MB，撞真机 uploadFile 通道/60s 超时。修复 = **成片规格预算**（OUT_ATTEMPTS 三档：2560/0.92 → 2048/0.85 → 2048/0.75，超 8MB 或画布失败自动降档闭环）+ `uploadCheckPhoto` 显式 timeout 120s。相册原图直传与服务端零改动 |
| R4 | 「横屏后你需要重新设计 UI」（截图：导航黑带压顶、取景剩一条、快门居中右侧全空） | 横屏专属布局：全屏取景、导航浮层化、快门右下（右手拇指）、完成/用照片其上、托盘左下横排、重拍左下、让出刘海侧；媒体查询 + isLandscape 双轨，竖屏布局不动 |
| R5 | 「水印拍出的照片**又**出现了无法上传」（2026-11-13 第三轮） | R3 只压了 quality 与长边，**漏了导出像素数**：`canvasToTempFilePath` 的 `destWidth` 默认 = 区域尺寸 × **devicePixelRatio**，DPR=3 的机子把 2560 宽输出成 7680 宽（44MP）→ 几十 MB。且**每一档都被同样放大**，闭环降到最后一档「无条件接受」照样几十 MB（= 「明明在降档还是传不上去」）。修复 = `destWidth/destHeight` 显式取 `canvas.width/height`（1:1）+ 体积读不到不再算通过（去掉 fail-open）+ 降档途中出错保留已产出成片。⚠️ 反向：**不要**传 `x/y/width/height`（区域默认整块画布；部分机型按 CSS 尺寸解释这几个参数，本页离屏画布 CSS 只有 320×240 → 会只导出左上角）。详见 round2 A5 |
