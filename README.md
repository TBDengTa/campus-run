# 校园跑小程序（唐唐快跑 2.0）

> 2.0 全新重写版：校园跑步打卡微信小程序（小程序端 + Node.js 后端，管理端内置于小程序）。
> 1.0 代码已遗失，2.0 基于旧 MongoDB 数据库结构逆向重建，并设计新表 + 一次性迁移方案。

## 功能总览

**角色与权限（单小程序统一登录）**

- **账号密码体系**：学生名单由学校提供（姓名/学号/身份证号），管理端导入后自动建号——**姓名为账号，身份证后8位或学号后8位为初始密码**，首次登录强制改密；教师账号由管理端创建
- **微信绑定**：账号首次登录即绑定当前微信，绑定后不可解绑，其他微信登录该账号会被拒绝；已绑定用户进入小程序自动登录
- 用户角色只有两种：**学生 / 教师**；"管理员"通过权限组授予，不是独立角色
- 权限系统 = **独立权限项**（看板/用户/申诉/广告/内容/配置/权限管理）+ **权限组**（如内置的"超级管理员组"= 全部权限、"教师管理组"= 可看可审不可改）
- 用户的有效权限 = 直接授予的独立权限 ∪ 所在权限组的权限；教师/管理员首页**优先显示管理内容**（核心指标 + 按权限过滤的管理入口），学生首页显示运动数据
- 名单导入：管理端粘贴/上传 CSV·JSON（按学号去重，同名同密码拒绝），预留学校后台推送 API（`POST /api/roster/push` + `X-Roster-Key`）
- 持有 `permission.manage` 权限者可在「用户详情 → 权限管理」中改角色、勾权限组、勾独立权限、重置密码

**用户端**
- 底部导航：**首页 / 跑步 / 记录 / 排行 / 我的**（自定义悬浮胶囊导航，中间「跑步」为凸起橙色圆钮）
- 微信运动步数同步（WeRun 解密）+ 每日/每周目标 + 分时段目标进度
- GPS 实跑（地图轨迹、距离/配速/卡路里）
- 运动记录（周统计 + 月历打卡点标 + 节假日标记 + 当日/本月记录列表）
- 步数排行榜（今日榜 / 本周榜 / 总榜 × 全校 / 本院系 / 本班）
- 看激励视频赚步数（每日限次）
- BMI 身体数据 → 自动匹配目标计划
- 喝水打卡
- 成就徽章（累计/单日/连续等 7 类条件）
- 学生认证（学校 → 院系 → 专业三级选择 + 学号实名）
- 封禁申诉
- 公告 / 版本日志

**教师端（同一小程序，登录后自动切换）**
- 教师账号**不参与运动记录与步数排名**：步数同步 / GPS 实跑 / 激励视频加步数均在服务端拦截（`403 + 403003`）
- 底部导航按角色变化：有管理权限 = 首页 / 管理 / 我的；无权限 = 首页 / 公告 / 我的
- 首页为教师视角卡片（管理入口 + 公告），不展示步数 hero 与同步按钮

**管理端（小程序内独立分包，仅管理员可见）**
- 数据看板（用户/活跃/步数/广告 PV 趋势）
- 用户管理（搜索/封禁/解封/流水）
- 申诉审核
- 广告系统（赞助商 / 广告位 / 素材 / H5 落地页托管 / PV·点击统计）
- 内容管理（公告 / 版本日志 / 节假日 / 组织架构 / 徽章定义）
- 系统配置（目标 / 反作弊阈值 / 激励视频规则）

**反作弊**：步数暴增检测、配速异常检测，命中自动封禁 N 天，支持申诉解封。

## UI 设计系统（白橙）

整体采用**白底 + 品牌橙**的简约风格，设计令牌与公共类集中在 `miniprogram/app.wxss`：

- 主色 `--tt-brand: #ff6b00`，浅底 `--tt-brand-soft`，页面底 `#f6f7f9`，卡片纯白 + 柔和大投影；
- TDesign 品牌变量（`--td-brand-color-*`）已整体改为橙色系，`t-button` / `t-tag` / `t-progress` 等组件默认即为白橙风格；
- 公共排版类：`.tt-card` `.tt-section` `.tt-stat-row` `.tt-grid` `.tt-row` `.tt-segment` `.tt-chip` `.tt-pill-btn` `.tt-empty` 等；
- 底部导航为**自定义 tabBar**（`custom-tab-bar/`）：白色悬浮胶囊 + 中间凸起橙色圆钮，按角色动态变化
  （学生 5 项；教师 3 项，教师不参与运动记录与排名）；图标用 `t-icon` 矢量图标，选中填充态 `/ #ff6b00`；
  `assets/tabbar/*.png` 由 `node tools/gen-tabbar-icons.js` 生成，作为关闭 custom 时的原生兜底
- 暗色模式令牌同样定义在 `app.wxss`，新增页面请勿硬编码颜色。

## 目录结构

```
├── project.config.json    # 微信开发者工具配置（miniprogramRoot 指向 miniprogram/）
├── miniprogram/           # 小程序前端（TDesign 组件库）
│   ├── pages/             # 用户端页面
│   ├── packageAdmin/      # 管理端分包
│   ├── custom-tab-bar/    # 自定义底部导航（悬浮胶囊 + 凸起圆钮，按角色变化）
│   ├── assets/tabbar/     # TabBar 位图图标（关闭 custom 时的原生兜底，由 tools 脚本生成）
│   ├── config/env.example.js  # 环境配置模板（复制为 env.js，不入库）
│   └── miniprogram_npm/   # 已构建的 tdesign-miniprogram
├── server/                # Node.js + Express 后端
│   ├── src/               # 路由 / 服务 / 模型 / 中间件
│   ├── scripts/           # 数据迁移、管理员引导
│   └── .env.example       # 环境变量模板（真实 .env 不入库）
├── docs/                  # 数据库设计 / API / UI 规范 / 迁移说明
└── tools/                 # TabBar 图标生成器
```

## 快速开始

### 后端

```bash
cd server
npm install
cp .env.example .env      # 填写数据库连接、JWT 密钥、微信 AppSecret
npm start                 # 默认 :3000
```

从 1.0 旧库迁移数据（可选）：

```bash
npm run migrate:dry       # 试运行，只出对账报告不写入
npm run migrate           # 正式迁移到新库
```

### 小程序

1. 微信开发者工具打开仓库根目录
2. 复制 `miniprogram/config/env.example.js` 为 `env.js`，填入后端地址
3. 本地无 AppSecret 也可测试：`env.js` 中 `DEV_LOGIN: true`，用 `DEV_ROLE` 切换 `dev-student` / `dev-teacher` / `dev-admin` 三种角色（后端需同样开启 `DEV_LOGIN=true`）
4. 详情 → 本地设置 → 勾选「不校验合法域名」（开发阶段）
5. 编译运行

## 部署清单（上线前）

| 事项 | 说明 |
|---|---|
| HTTPS 域名 | 后端部署到合法域名下，在小程序后台配置 **request 合法域名** |
| 业务域名 | 广告落地页（`/p/:slug`）所在域名需加入 **业务域名**（web-view 使用） |
| 图标字体 | TDesign 图标走 CDN（tdesign.gtimg.com），需加入 **downloadFile 合法域名** |
| 微信 AppSecret | 后端 `.env` 的 `WX_APPSECRET`（code2session / WeRun 解密必需） |
| 微信运动 | 小程序需具备「微信运动」类目权限（沿用 1.0 appid 则已有） |
| 流量主 | 激励视频广告位 ID 在 `miniprogram/pages/reward/reward.js` 中替换 |
| 管理员 | 方式一：`.env` 的 `ADMIN_BOOTSTRAP_OPENIDS`（登录自动授予超级管理员权限组）；方式二：`npm run admin:add -- <openid>`；方式三：管理员在小程序「用户详情 → 权限管理」里勾选权限组 |
| JWT_SECRET | 务必设置为随机长字符串 |

## 安全约定

- 仓库不含任何服务器地址、数据库凭据与密钥：后端配置在 `server/.env`（已 ignore），前端配置在 `miniprogram/config/env.js`（已 ignore）
- 管理端权限在服务端二次校验（JWT + role），前端入口隐藏只是第一道门
